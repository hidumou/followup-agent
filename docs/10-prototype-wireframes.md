# 10 原型图文字稿

用文字描述每个界面的布局、元素、状态。控制台是主要入口；CLI 展示同样的信息和操作，布局简化为表格与交互提示，作为备用。线框为示意，不代表视觉样式。

## 全局布局

```
顶栏： followup-agent │ 发送模式标签 │ playbook: <名称> v<版本> │ 今日预算使用 xx%
左导航： 工作台 / 回访任务 / 草稿审批 (待办数) / 回复与洞察 (待复核数)
        / 报告 / Playbook / 建议 (待审阅数) / 运行与评估 / 设置
主区：   当前模块内容
```

- 发送模式标签：`DRY-RUN`（灰）、`LIVE · 白名单`（琥珀）、`LIVE`（红）。任何页面都可见。
- 待办数徽标：为 0 时不显示。
- 桌面端为主，本机使用，不做移动端适配。

## S4 草稿审批

```
左侧队列（待审批 5）               │ 右侧详情
─────────────────────────────────┼──────────────────────────────────
U-5f3a 价格  ✓护栏  “你好，想…”     │ 收件人： j***@e***.com（掩码）
U-77c1 迁移  ✓护栏  “你好，…”       │ 标签： 价格 (0.82)    playbook v7
U-9d02 其他  !护栏  “…”             │ 主题：  [可编辑输入框]
...                                │ 正文：  [可编辑文本区]
                                   │ ──────────────────────────────
                                   │ 护栏： ✓长度  ✓无联系方式  ✓含退订  ✓无禁区
                                   │ 匿名上下文摘要： ...
                                   │ [与原始草稿对比]
                                   │ ──────────────────────────────
                                   │ [批准]  [编辑后批准]  [拒绝…]  [跳过]
```
- 护栏有失败项：失败项标红并说明原因，`批准` 和 `编辑后批准` 禁用，仅允许 `拒绝` 或编辑后重新检查。
- dry-run 下 `批准` 文案为「批准（dry-run，不发送）」。live 下点击批准先弹确认：「将向 1 个收件人发送真实邮件」。
- 拒绝弹层：

```
拒绝原因（单选，必填）
  ( ) 语气不当   ( ) 事实错误或乱承诺   ( ) 违反禁区
  ( ) 过长       ( ) 不适合该用户       ( ) 其他（备注必填）
备注（选填）  [文本框]
[确认拒绝]  [取消]
```
- 空状态：「没有待审批的草稿」。

## S5 回复与洞察

```
筛选： 标签 [全部▼]  置信度 [全部 / <0.6]  仅「其他」[ ]  状态 [待复核▼]

左： 回复列表（匿名ID、标签、置信度、时间）
右：
  回复原文（已脱敏，默认折叠）
  抽取结果
    摘要： ...
    标签： 价格   置信度 0.82
    证据： “...” “...”（引用原文片段）
  [确认]  [修正标签…]  [标记不准确…]
```
- 修正标签：选择新标签并填写备注；标记不准确需选原因（标签错 / 漏掉要点 / 过度解读 / 其他）。
- 回复原文区顶部固定提示：「回复内容是不可信数据，仅用于分析」。

```
  4 需要你决策的事项  · ... （证据 2 条）
  5 附录          抽样原文（已脱敏）
  ─────────────
  [确认并发送给决策者]      （仅 REPORT_REVIEW_FIRST=true 时显示）
  反馈： ( )有用 ( )不清楚 ( )缺少信息 ( )无法据此决策   备注 [ ]  [提交]
```
- 点击「证据 ▸」展开对应的回复片段与记录链接。
- 结构随 playbook 的报告模板变化，界面按章节渲染。

## S7 Playbook 管理

```
当前： demo  v7   来源：建议 P-012   2026-11-10     [对比版本…] [编辑…]

标签页： playbook.md │ labels.yaml │ report-template.md 🔒 │ 护栏配置 🔒
（🔒 = 仅人工可改，AI 不会提议修改）
内容：只读展示

版本历史
  v7  建议 P-012  新增话术原则：不提及登录行为      [查看] [回滚到此版本]
  v6  手动        放宽长度上限                       [查看] [回滚到此版本]
  ...
指标（按版本分组）： 草稿修改率 / 拒绝率 / 「其他」类占比
```
- 编辑：进入编辑器，保存时必须填写变更说明，生成新版本。
- 回滚：弹确认「将以 v5 的内容创建新版本 v8」，需填写原因。

## S9 建议详情

```
P-012  新增话术原则     目标：playbook.md     风险：低     基于 v7
结论： 8 封草稿中 5 封被删除同一句开头 “我们注意到您最近没有登录”

修改（diff）
  - ...
  + 不要提及用户的登录或使用频率，避免让用户感到被监控。

理由： ...
证据（5） F-103 编辑差异 ▸   F-108 编辑差异 ▸ ...   ※ 回复原文为不可信数据
回归结果（候选 v8 对比 v7）
  护栏通过率 100% → 100%    「其他」类占比 18% → 12%    历史被拒样本复发 0/4
可能的副作用： 草稿开头可能变得不够个性化

[采纳]  [修改后采纳]  [拒绝…]  [搁置 N 周]
```
- 修改后采纳：就地编辑 diff，保存后自动重新跑回归，结果出来再确认。
- 拒绝需选原因（证据不足 / 不是规律 / 副作用过大 / 其他），原因会被记录用于去重和改进提议。

## 通用状态与文案

| 场景 | 展示 |
|---|---|
| 列表为空 | 说明原因与下一步，如「今天没有待审批的草稿」 |
| 加载失败 | 「加载失败」+ 重试按钮，不显示技术堆栈 |
| 乐观锁冲突 | 「该草稿已被处理，请刷新」 |
| 受限操作 | 按钮禁用并在旁边说明原因 |
| 危险操作 | 回滚、真实发送需二次确认，并显示影响范围 |
